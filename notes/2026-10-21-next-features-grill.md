# YOYO 後續功能：訪談決策紀錄

Date: 2026-10-21（Asia/Taipei） · Goal: 確認一般文字工具與工程師工具的範圍、操作方向及交付順序。

本紀錄於訪談結束後依對話補錄。訪談期間處於規劃模式，未逐題寫入檔案；本檔不是當時已完成逐題存檔的聲明。

## Summary / key decisions

- 先新增一般文字整理工具，再交付工程師與開發工具。
- 一般文字工具優先服務從網頁、PDF、聊天貼上內容的整理情境。
- 文字清理、去重、統計使用獨立網址及共用工作區；採保留結構的輕度清理與結果預覽。
- 支援貼上、UTF-8 TXT 匯入、複製與 TXT 下載，一次處理一份文字。
- 使用者特別補充：「之後還是要討論專業面向功能」。專業面向是本次必要範圍。
- 工程師工具三類「以上都要」：JSON／差異比對、編碼／時間、正規表示式。
- 專業工具定位為完整的日常工具，免登入、本機處理；本批不做保存工作內容或流程編排。
- 比對支援一般文字與 JSON 資料兩種模式；正規表示式先支援 JavaScript。
- 使用者以「應該沒有 生成計劃」結束補充，授權產生本次實作規劃。
- 後續實作補充：專案須考慮 i18n；繁中介面下英文名稱、用途和同義詞也必須可搜尋。

## Q&A log

- Decision: 保持本階段繁體中文介面，工具展示資料依語系維護，目錄索引中英名稱／用途／同義詞；暫不增加未要求的語言切換器。
- Flags: 完整英文 UI 翻譯未納入本階段；未來新增 UI 語系時再補整套訊息字典。

### Q6 — 輸入與匯出
- Asked: 貼上加 TXT、僅貼上與複製、或直接讀取 PDF／Word？
- Captured: 「貼上加 TXT 檔案 (Recommended)」。
- Decision: UTF-8 純文字，一次一份；可複製及下載，不直接解析 PDF／Word。

### Q7 — 工程師核心任務
- Asked: API／JSON、編碼與時間、或正規表示式？
- Captured: 「以上都要」。
- Decision: 三組能力全部納入。

### Q8 — 專業工具深度
- Asked: 完整日常工具、保存型個人工具台、或可串接流程？
- Captured: 「完整的日常工具 (Recommended)」。
- Decision: 編輯器、錯誤定位、設定與預覽；免登入、本機處理。

### Q9 — 比對模式
- Asked: 文字及 JSON 雙模式，或先做文字比對？
- Captured: 「文字與 JSON 兩種模式 (Recommended)」。
- Decision: JSON 物件欄位順序不構成資料差異，陣列順序有意義。

### Q10 — 正規表示式語法
- Asked: JavaScript，或多語言引擎？
- Captured: 「JavaScript 語法 (Recommended)」。
- Decision: 比對、群組擷取及取代預覽；需要可中止的執行機制。

- Captured: 「先文字、再工程師工具 (Recommended)」。
