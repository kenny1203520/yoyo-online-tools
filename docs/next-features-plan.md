# YOYO 工具站：文字與工程師工具實作計畫

日期：2026-10-21（Asia/Taipei）

狀態：訪談結束後的實作規劃；本文新增功能尚未實作。

## 1. 目標、決策與交付順序

延續 YOYO 的繁體中文、暖白與青綠介面，讓一般使用者整理貼上的文字，也讓工程師完成日常資料檢查及除錯。所有新增工具免登入、在瀏覽器處理，不新增雲端 API、不保存使用者內容。

本次順序取代舊路線中「圖片後先做登入與雲端」的安排：

| 階段 | 交付 | 完成判準 |
| --- | --- | --- |
| A：一般文字工具 | 分類目錄、文字清理、重複行處理、字數統計與共用文字工作區 | 使用者能找到工具、貼上／匯入、調整規則、確認結果、複製／下載；既有圖片流程未退化 |
| B：工程師工具 | JSON、文字／JSON 比對、Base64、URL 編解碼、時間戳及 JavaScript 正規表示式 | 六項工具的核心任務、錯誤處理、效能保護與跨裝置驗收完成 |
| 後續另案 | 帳號、雲端、配額、表格、進階專業及團隊功能 | 先確認實際任務與資料生命週期，再訂規格 |

B 階段可依 JSON → 比對 → 編碼與時間 → 正規表示式的順序開發，但全部都屬於已確認範圍。A 可先獨立發布；不預估未經開發量測的工期。

**已確認事項**：先文字再工程師；專業三類全部要；一般文字採輕度清理；三入口共用工作區；貼上與 UTF-8 TXT；文字／JSON 雙比對；JavaScript 正規表示式；完整日常工具定位。

**本計畫補足的工程預設**：以下列出的具體清理規則、計數算法、編輯器、上限、逾時及網址，由本次規劃提出，並非使用者逐項指定。實作依此進行，若實測需要調整資源上限，須同步更新介面與文件。

**i18n 決策（2026-10-21 更新）**：使用者已確認完整繁中／英文介面、`/zh-TW`／`/en` 語言路由與切換控制。新工具必須補齊兩語文案、錯誤、SEO 與跨語言搜尋案例；切換語言保留工作區內容。詳見 [多語言與部署決策](i18n-seo-deployment.md)。

## 2. 共用體驗與架構

### 目錄與導覽

- 首頁提供「全部、圖片、文字」分類，分類與名稱／用途／同義詞搜尋共同篩選；繁中 UI 可用英文查詢，例如 `resize image`、`clean text`。文字和圖片工具的可見名稱與說明由 i18n 資料提供。只顯示已可用工具；階段 B 完成前不展示不可操作入口。
- 首頁主文案由圖片專用改為日常工具定位；各工具頁各自提供用途、範例、限制、操作說明與搜尋 metadata。保留既有圖片網址。
- 延續現有配色、繁體中文系統字型與 Lucide 圖示。桌機原文／結果並排；手機原文、規則、結果垂直排列。程式碼編輯區可自行橫捲，但不能造成整頁橫向溢出。
- 示例只用合成資料，使用者點選才填入。載入範例／匯入檔案若會覆蓋非空原文，需明確確認。清空保留一次還原機會。

### 工具資料與路由

- 將 `src/lib/tools.ts` 從圖片專用結構擴充為可辨識工作區種類的工具聯集；保留名稱、slug、用途、關鍵字、圖示與網址，新增 `category`、`workspaceKind`、`status`、`processing: "local"`，圖片設定只放在圖片類型。
- `src/app/tools/[slug]/page.tsx` 依工具種類選擇對應工作區；各頁說明與 metadata 留在伺服器層，處理與編輯器模組在需要的 client 工作區才載入。
- 共用工具登錄包含 `zh-TW`、`en` 顯示字串和搜尋詞，供首頁、導覽、靜態路由產生與 metadata 使用；搜尋比對經 NFKC 正規化、英文大小寫／重音折疊及英文常見複數變體，先比完整詞組，再要求所有剩餘詞元皆命中。不依賴目前顯示語系。未知／未發布 slug 回傳 404。補測分類搜尋，避免新增圖示沿用目前圖片專用的條件判斷。
- 文字三入口共用同一個 session state。切換入口只改焦點／展開的面板，不覆蓋原文或使用者已選設定。第一次直接進入時才套用該工具預設。支援上一頁／下一頁與正確頁面標題。
- 原文、設定、工作結果只保存在該工作區記憶體；重新整理或離開工作區後清除。不把內容放進 URL、localStorage、IndexedDB、遙測或錯誤日誌。其他工程師工具各有獨立工作階段，不建置跨工具流程編排。

### 最小內部介面

- `TextSession`：原文、來源檔名、清理及去重設定、目前工具、輸入版本。
- `ToolJob`：工作種類、輸入、設定、`requestId`；`ToolResult`：同一 ID、輸出、統計及診斷資訊。
- 工作狀態統一為 idle／running／success／error／cancelled；診斷包含可讀訊息與可選的行、欄、位置。輸入或設定變更後，舊結果立即失效，禁止誤複製或下載。
- 處理函式與 React UI 分開；純轉換函式可單獨測試。昂貴計算放 Web Worker；用輸入版本及 request ID 丟棄過期回應。取消／逾時會終止並重建 Worker，卸載時清理 Worker 與下載 Object URL。
- 一般文字採原生文字欄位與可讀結果區；工程師編輯器選用按需載入的 CodeMirror 6，提供行號、JSON 高亮、錯誤定位與可及標籤。不得攔截使用者離開編輯器所需的鍵盤操作。

## 3. 階段 A：一般文字工具

### 入口與流程

| 入口 | 初次進入的預設 |
| --- | --- |
| `/tools/text-cleanup` | 展開清理設定，啟用輕度清理 |
| `/tools/remove-duplicate-lines` | 展開去重設定，啟用逐行去重，其他內容轉換關閉 |
| `/tools/word-count` | 以統計為主，不自動修改原文 |

流程為貼上／匯入 → 選規則 → 預覽與統計 → 複製／下載。保留可編輯原文與唯讀結果；輸入停止 300ms 後更新結果，計算未完成時顯示狀態。所有入口均可啟用清理與去重；切換工具不把輸出再當原文，以免操作反覆累積。

### 清理與去重規則

- 清理預設：換行統一為 LF、移除每行尾端空格／Tab、將連續空白行縮成一個空白行、去除文件頭尾空白行。保留行首縮排、行內空格、單一換行與段落。
- 另選操作：移除每行行首空白、合併段落內單一換行。合併以一個空格連接，保留空白行的段落邊界；明示這是機械轉換，不宣稱能辨識 PDF 版面。不得預設執行。
- 不預設轉換全半形、標點、大小寫、Unicode 正規化或刪除重複內容；本批不新增自動改寫、排序及 PDF／Word 解析。
- 固定順序：換行標準化 → 已選空白規則 → 已選斷行規則 → 已選去重。介面顯示已啟用規則，提供全部還原。
- 去重以處理後的逐行字串做完全相同比對，區分大小寫、保留第一次出現與原順序；空白行遵循清理設定，不當作重複項目刪除。提供「比對時忽略頭尾空白／忽略大小寫」選項，預設關閉；只改比較方式，不修改保留行的文字。

### 統計與檔案

- 原文及結果顯示字元數（含／不含空白）、中文字數、英文單字數、行數、UTF-8 位元組數，以及移除的重複行數。
- 字元以 Unicode grapheme cluster 計算；中文字數明示為 Unicode Han 字元數；英文單字以連續拉丁英文字母計數，允許單字內的撇號／連字號；不把中文無空格文章當成一個英文單字。
- 行數依標準化換行切分：空字串為 0 行，結尾換行代表最後一個空行。介面提供計數定義。使用 `Intl.Segmenter` 的能力檢測；不可用時明示字元計數限制，不以 UTF-16 長度偽裝同一算法。
- 檔案匯入僅接受 UTF-8 `.txt`，允許 UTF-8 BOM 並移除。解碼失敗顯示請轉存 UTF-8，避免以替代字元默默破壞內容。原文與結果顯示為純文字，不解讀 HTML。
- 一次一份內容，輸入上限 1 MiB UTF-8；貼上與檔案匯入採相同規則。輸出為 UTF-8 無 BOM TXT，預設 `<原檔名>-cleaned.txt`，貼上文字用 `yoyo-text.txt`。
- 複製失敗時保留結果並提供可手動選取的替代操作。處理中的輸出不允許匯出；空內容保持中性空狀態。

## 4. 階段 B：工程師日常工具

六個入口各有可分享網址、合成範例、輸入限制與錯誤說明；不共享含使用者內容的 URL。文字檔匯入及輸出使用共用檔案介面，JSON 工具另接受 UTF-8 `.json`；不提供多檔批次。

| 工具／網址 | 第一版完整能力與規則 |
| --- | --- |
| JSON `/tools/json-formatter` | 格式化、壓縮、驗證、行欄錯誤定位；縮排預設 2 空格，可改 4 空格或 Tab。接受標準 JSON 任意頂層值；不接受註解、尾逗號或重複鍵。保留原欄位順序及數字精度，禁止經一般浮點解析後改寫大整數。輸出可複製／下載 `.json`。 |
| 比對 `/tools/text-diff` | 左右兩份內容；文字模式以行比較，預設忽略 CRLF／LF 差異，其餘空白有意義，可另選忽略行尾空白。JSON 模式以結構和值比較：忽略物件欄位順序，陣列按索引比較，區分缺值、null 與型別；數值 1 與 1.0 視為相等且不損失大數值精度。顯示新增、刪除、修改與 JSON 路徑；無效輸入先定位錯誤。手機提供單欄差異視圖；可複製／下載 UTF-8 文字差異摘要，不宣稱是可套用的 patch。 |
| Base64 `/tools/base64` | UTF-8 文字編碼與解碼，支援標準 Base64／Base64url，預設標準；能處理中文及 emoji。非法字元、填補規則或非 UTF-8 二進位結果顯示明確錯誤；不擅自修改輸入。暫不處理二進位檔或圖片 data URL。 |
| URL `/tools/url-encode-decode` | 編碼／解碼，明示「參數值」與「完整網址」模式，預設參數值；只處理一層，不自動反覆解碼。無效百分比編碼顯示錯誤；一般模式保留 `+` 字元，不把它默認當表單空白。不存取輸入的網址。 |
| 時間戳 `/tools/unix-timestamp` | Unix 時間戳與 ISO 8601 日期時間雙向轉換；秒／毫秒由使用者明選，預設秒，不用位數猜測。日期輸入要求明確時區偏移或 Z；同時呈現 UTC、Asia/Taipei 與裝置本地時間。提供「填入現在」，拒絕不存在的日期及超出範圍的數值；秒模式最多支援毫秒精度，不靜默捨去額外精度。 |
| 正規表示式 `/tools/regex-tester` | JavaScript 語法，比對高亮、群組與命名群組、匹配數、取代預覽。輸入 pattern 不含外圍斜線；旗標獨立選取，預設 g。依瀏覽器能力顯示可用旗標及說明，不承諾 PCRE／Python 相容。替換字串遵循 JavaScript 規則；不執行使用者 JavaScript。處理零長度匹配、非法規則、無結果與逾時。 |

### 精度、資源與執行保護

- JSON 採 `lossless-json` 解析／序列化，沿用其保留數字字面值及拒絕重複鍵的能力；與 UI 錯誤行欄轉換分離。結構比對的數值相等以十進位係數／指數正規化處理，不轉成 JavaScript Number。不把資料鍵合併進設定或應用物件。
- 一般工程師輸入每欄上限 1 MiB UTF-8；雙欄比對最多合計 2 MiB、每側 10,000 行；JSON 深度上限 200。編碼膨脹後輸出上限 4 MiB，超限時明確報錯，不下載截斷結果。
- JSON／比對計算放 Worker，單次上限 5 秒；呈現差異最多 2,000 項，超限顯示需縮小輸入，不把截斷內容稱為完整報告。
- Regex 測試文字上限 100 KiB、pattern 上限 4 KiB；在專用 Worker 執行，單次超過 2 秒即終止，提供取消及重試。最多 1,000 個匹配，超限提示縮小資料，不提供不完整取代結果的匯出。
- 一般工具可在輸入停止 300ms 後預覽；比對及 Regex 由「開始比對／測試」明確觸發，避免每次輸入都啟動昂貴任務。設定變更立刻將舊結果標為未更新。
- Worker 或必要瀏覽器能力不可用時，顯示受影響工具的限制與處理方式；不把危險運算退回主執行緒。以上上限為資源保護，不是裝置效能保證。

## 5. 實作、驗收與發布

### 實作順序

1. 保存本計畫及訪談紀錄，整理工具登錄／路由分派與共用分類 UI，保留目前工作區中的既有修改。
2. 建立文字純轉換模組、session、Worker 回應版本機制及輸入／匯出介面；接上三個文字入口。
3. 完成 A 的驗收與現有圖片功能回歸，再發布 A。進階工具不使用「即將推出」空入口。
4. 按需加入 CodeMirror 6 與精度安全的 JSON 解析；依 JSON、雙模式比對、編碼／時間、Regex 順序完成 B。
5. 完成 B 驗收、各工具說明、README 與限制文件後發布 B。沿用現有 Next.js 專案，本批不為新增工具另做框架升級或導入後端。

### 必測情境

| 類別 | 驗收案例 |
| --- | --- |
| 目錄與路由 | 分類＋關鍵字交集、中英同義詞、混合語言、大小寫、英文複數、重音字元、無結果、直接網址、未知網址、metadata；三個文字入口切換及上一頁／下一頁保留 session。 |
| 一般文字 | 中文／英文／emoji／組合字元、CRLF、空文字、空白行、縮排、行內空格、尾端換行、合併斷行開關；不改原文、不累積處理。 |
| 去重與統計 | 保留首行及順序、大小寫／頭尾空白選項、空行處理、數字／英文詞／漢字及 grapheme 定義；原文與結果統計一致。 |
| 檔案與結果 | UTF-8 BOM、非法 UTF-8、超限貼上與檔案、覆蓋確認、剪貼簿拒絕、正確檔名及 UTF-8 下載；失效／取消／逾時結果不可匯出。 |
| JSON 與比對 | 大整數、長小數、指數、重複鍵、特殊物件鍵、非法 JSON、深度超限、缺值與 null、陣列順序、物件欄位重排、1 與 1.0；錯誤定位與數值精度均正確。 |
| 編碼與日期 | 中文與 emoji 往返、Base64url、非 UTF-8 解碼、非法百分比、保留 `+`、單層解碼、秒／毫秒切換、負時間戳、UTC／台北／裝置時區、閏日與非法日期。 |
| Regex 與併發 | 捕獲群組、命名群組、零長度匹配、旗標能力、替換語法、災難性回溯、取消／2 秒中止、超量匹配，以及新輸入不被舊 Worker 回應覆蓋。 |
| 隱私與回歸 | 用網路紀錄確認輸入及檔案未外送；內容不寫入持久儲存或日誌；離開後釋放資源；原圖片搜尋、設定、處理、切換與下載仍可用。 |

- 工程檢查：lint、typecheck、生產建置；純轉換採 Vitest，關鍵瀏覽器流程採 Playwright。測試聚焦上述資料完整性與互動行為，不只重複實作細節。
- 桌面 Chrome、Edge、Firefox、Safari 與手機 Safari、Chrome 驗收；375、768、1024、1440px，含鍵盤主流程、可見焦點、欄位標籤、讀屏錯誤與非色彩差異標記。Playwright WebKit 不當作實機 Safari 已驗收。
- 先使用可用瀏覽器完成自動化及人工檢查；無法取得的裝置具體記錄為未驗收，不以建置成功取代。
- A 邀請 3–5 位一般使用者無引導完成整理文字、去重與下載；B 邀請 2–3 位工程師完成 JSON 查錯、資料比對及 Regex 取代。任務失敗或會造成資料誤用的問題修正後才標記完成。
- 部署方式已確認為 GitHub Actions 驗證與公開 GHCR 映像，支援 Linux AMD64／ARM64 自行部署；所有新工具沿用這套 CI 與 SEO 規範。發布前先取得對應驗收紀錄。效能及錯誤只在測試中量測，本批不新增包含使用者內容的分析服務。

### 不在本批範圍

帳號、雲端與免費配額、內容歷史、跨裝置同步、收藏、流程編排、多人協作、PDF／Word 解析或 OCR、CSV／Excel 整理、圖片新功能、JWT、API 發送器及其他語言的 Regex 引擎，均另訂後續規格。
